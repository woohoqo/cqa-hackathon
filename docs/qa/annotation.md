# Независимая человеческая разметка

Откройте `qa/annotation.html`, выберите локальный DEV JSON и `qa/manifest.json`. Данные обрабатываются в браузере без внешних ресурсов. Сам HTML не содержит разговоров. Сохраняйте результаты кнопкой экспорта; не коммитьте заполненные формы.

1. Разметчики A и B отдельно проходят шесть пилотных разговоров. Не показывать им ответы AI и друг друга. Каждый владеет одним экспортом с собственным `annotator_id`.
2. На каждый критерий выбрать ответ/ступень, указать существующие message IDs, короткое обоснование. Для отсутствующего действия — участок, где оно ожидалось. Для N/A — конкретное условие неприменимости. Пустое поле означает неготовую разметку, а не N/A.
3. Спорные решения сохранять как `disputed`, с причиной; не принуждать разметчика к уверенной метке. Язык/дикция/неясный ASR и недостаточные сведения о продукте — допустимые причины спора.
4. После независимого заполнения сравнить A/B: по каждому критерию количество пар и разногласий, отдельно N/A и №8. При расхождении обсудить доказательства, при необходимости привлечь третьего человека. Нельзя объявлять ответ AI решающим голосом.
5. Зафиксировать трактовки и финальное решение согласования с `source=human_adjudicated`, двумя исходными annotation IDs, именем/псевдонимом согласовавшего и причиной. Исходные A/B остаются неизменными. Нельзя просто переименовать `human_individual` в `human_adjudicated` без согласования.
6. Завершить 26 разговоров тем же способом; минимум полностью двойная разметка пилота и всех спорных/критических случаев. Для честного отчёта отмечать, какие остальные случаи проверены одним или двумя людьми. Строгий comparison принимает только согласованные complete-метки выбранного источника.

## Сравнить два файла и сохранить решение

`qa.adjudicate` читает два независимых экспорта формы и manifest. Реальные транскрипты и API ему не нужны. По умолчанию сравнивается только пилот; для остальных частей явно задайте `--subset tuning`, `--subset holdout` или `--subset all`. Сначала оба человека заканчивают независимый разбор; только затем им показывают разногласия.

```powershell
python -m qa.adjudicate compare C:\private\annotator-A.json C:\private\annotator-B.json qa\manifest.json --output C:\private\review.json --report C:\private\disagreements.md
```

Отчёт показывает пары и разногласия по всем восьми критериям, отдельно N/A, статусы A/B и незаполненные ответы; JSON также содержит результаты по языкам. Согласие двух людей — отдельный показатель, не точность AI. Черновики/спорные ответы могут входить в описательное сравнение заполненных пар, но их статус остаётся виден. Отсутствие ответов даёт `null`, а не 100% согласия.

После обсуждения проверяющий заполняет только `records[].decision` в `review.json`:

- `status`: `complete` после решения; `draft` или `disputed`, если решение не принято.
- `reviewer_id`, `reviewed_at` в ISO 8601 с часовым поясом, `rationale`: кто, когда и почему согласовал.
- Все восемь `criteria`: допустимый `answer`, существующие `evidence[].message_id`, содержательный `comment`. Для N/A объясните условие; для отсутствующего действия — место, где оно ожидалось.

Затем:

```powershell
python -m qa.adjudicate finalize C:\private\annotator-A.json C:\private\annotator-B.json qa\manifest.json C:\private\review.json --output C:\private\adjudicated.json
```

Инструмент заново читает оригиналы, сверяет хеши и не принимает правки исходных записей в review. Для завершённого решения нужны оба индивидуальных разбора со статусом `complete` или `disputed`; отсутствующий разбор или `draft` блокирует согласованную метку. Совпадения A/B не заполняют финальные ответы автоматически. Оригинальные JSON-объекты A/B, их SHA-256, полный review и ID незавершённых решений сохраняются в результате. Исходные файлы не перезаписываются.

Форма пока не назначает `annotation_id`: утилита выводит стабильный ID `sha256:<хеш исходной записи>` для каждой разметки. Изменение ответа, комментария или автора меняет этот ID. Для сравнения AI перенесите массив `references` из `adjudicated.json` в приватный run-context для `qa.export_run`; не используйте массивы исходных A/B или `review` как готовый эталон.

Хеши защищают от случайного смешивания версий, но не доказывают личность автора, независимость людей или правильность ответа. Это обеспечивает команда. JSON, review и Markdown держать вне Git: свободные комментарии могут содержать персональные данные. Содержимое holdout и индивидуальные ошибки не передавать AI-разработчику.

## Правила, которые чаще вызывают расхождения

- Оценивается оператор. Приветствие бота не заменяет приветствия/представления оператора. Реплики клиента, бота и системы важны как контекст.
- №2: уже известную информацию нужно учитывать, а не повторно спрашивать. N/A применим только когда исходных деталей хватало.
- №3: согласие пройти проверку не равно подтверждённой идентификации. Общая консультация может не требовать её. В замаскированных звонках нельзя домысливать скрытые сведения; спор фиксировать явно.
- №4: правильный следующий шаг может быть полным ответом. Неполная консультация и ясность общения — разные критерии. N/A допустим только если запрос ещё не был сформулирован.
- №6: только 0/4/7/10, вес 15. Порог первой реакции в три минуты, теги и вложения не оцениваются. При звонках транскрипт не даёт оснований оценивать дикцию/интонацию без прослушивания.
- №7: обрыв до возможности завершить и закрытие оператором без прощания — разные случаи. N/A объясняется причиной, а не отсутствием последней реплики.
- №8: достаточно предложения платной услуги в обход компании, согласие/оплата не нужны. Оскорбление, обход компании и раскрытие конфиденциального — три основания. Флаг не обнуляет балл.

## Источники нельзя смешивать

| source | Что означает | Как использовать |
|---|---|---|
| organizer_gt | Отдельный официальный эталон организаторов | Точность относительно официального источника; сейчас не предоставлен |
| human_individual | Независимый ответ одного человека | Пилот, разногласия, согласование; не готовый эталон |
| human_adjudicated | Согласованное людьми решение | Отдельный показатель относительно человеческой разметки |
| model_proposal | Автоматически предложенная метка | Только черновик/согласие моделей; не Ground Truth |

На этом этапе автоматическая разметка не создана, человеческие ответы не заполнены. Проценты точности не рассчитаны. В форме используется локальная QA-нумерация `<conversation_id>:m0001`; она соответствует порядку исходных сообщений, а не обещанию производственного message ID. Экспортный адаптер сравнивает ответы и итоги; автоматического сопоставления evidence с QA-ID в нём пока нет. При проверке доказательств сопоставляйте сообщения по исходному порядку со сверкой роли и текста; изменение порядка/текста требует нового сопоставления.
