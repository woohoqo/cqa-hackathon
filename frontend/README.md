# CQA frontend

Русский интерфейс React + Vite + TypeScript для общего FastAPI API `/api/v1`.
Начальная конфигурация и все оценки загружаются с backend. Критерии и их ID не зашиты в компоненты.

## Запуск

Нужны Node.js 22.12+ и pnpm 11. Сначала запустите backend по корневому README на `127.0.0.1:8000`.
Из корня репозитория:

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://127.0.0.1:5173`. Vite перенаправляет `/api` и `/health` на backend.
Если порт backend другой, задайте `CQA_BACKEND_URL` в локальном `frontend/.env` по `.env.example`.
Обычный запуск всегда обращается к настоящему серверу.

```bash
pnpm test
pnpm build
```

Сборка находится в `dist/`. Для размещения обслуживайте её вместе с reverse proxy `/api/v1` на FastAPI
или задайте публичный `VITE_API_BASE_URL` при сборке и разрешите origin в backend CORS.
Маршруты интерфейса используют hash и не требуют server-side SPA rewrite.
Ключи модели и подписанная ссылка организаторов должны оставаться в backend `.env`.

## Экраны и сценарий

1. **Диалоги**: импорт JSON-файла/текста либо набора организаторов с `group_id` (DEV по умолчанию),
   поиск ID, фильтры языка/канала/статуса/грубой ошибки, выбор до 100 диалогов и запуск.
   JSON принимает `ImportRequest.conversations`, массив `ConversationInput` или исходный конверт организаторов.
   Для исходного конверта frontend только преобразует названия полей в согласованный импорт;
   source `organizer:{group_id}` совпадает с backend для одинаковой идентичности диалогов.
2. **Карточка**: исходный транскрипт с четырьмя ролями и неизменёнными метками времени, история запусков,
   автоматический и окончательный итог, отдельный флаг нарушения, результаты секций,
   критерии и переходы к одному/нескольким сообщениям с подсветкой и фокусом.
   Для `false` отображается проверенный участок; N/A показывает причину и условие.
   Для HTTP(S) `audio_url` доступны плеер и внешняя ссылка. Точного audio seek нет: контракт не задаёт
   подтверждённое соответствие исходных меток времени и аудио.
3. **Чек-листы**: динамические критерии и секции, boolean/scale/flag, вес, ступени и их описания,
   N/A и условие. Сохранение создаёт новую неизменяемую версию. Кнопка «Оценить с версией N»
   выбирает возвращённый сервером ID; затем отметьте диалоги и запустите оценку.
   Черновик сохраняется при переходе между разделами; перед потерей черновика при смене версии есть предупреждение.
4. **Апелляции**: выбранная оценка и критерий, комментарий, исходные доказательства. Режим «Проверяющий»
   вверху позволяет подтвердить оценку либо заменить ответ, обоснование и доказательства с причиной.
   Автоматическая оценка, решение человека и окончательная оценка показаны раздельно.
   Это переключатель действий для хакатона, регистрация не требуется.

Все баллы, веса, итоги и секционные результаты приходят с backend. UI только форматирует числа;
баллы критериев показываются до нормализации N/A, что явно подписано. `null` и `0` различаются.

## Синтетическая проверка интерфейса

Пример импорта: `examples/synthetic-dialogues.json`. Он явно помечен как синтетический.
Для воспроизводимой проверки успешных ответов до подключения AI есть отдельный opt-in сервер
`tests/fixture_server.py`. Он использует настоящий FastAPI, валидацию, расчёт и хранение апелляций,
но отдаёт **искусственные ответы критериев**. Это не финальное демо и не проверка качества модели.
Без явного `CQA_SYNTHETIC_UI_TEST=1` сервер не запускается. База временная.

Из корня репозитория, в окружении с установленными backend-зависимостями:

```bash
CQA_SYNTHETIC_UI_TEST=1 python -m uvicorn frontend.tests.fixture_server:app --host 127.0.0.1 --port 8001
```

В другом терминале:

```bash
cd frontend
CQA_BACKEND_URL=http://127.0.0.1:8001 pnpm dev --port 5174
```

В PowerShell задавайте переменные через `$env:CQA_SYNTHETIC_UI_TEST='1'` и
`$env:CQA_BACKEND_URL='http://127.0.0.1:8001'` перед соответствующей командой.
Никогда не используйте этот сервер как финальную оценку реальных диалогов.

## Интеграция

Реализация использует согласованный контракт, опубликованный в `main` (`91c22d4`). Обязательные
изменения API для четырёх экранов не нужны. Backend должен иметь реализованные endpoint-ы из `contracts/README.md`.
Для финального демо интегратору нужно подключить опубликованный AI-провайдер из PR #5 (`feat/ai`),
настроить модель/ключ на backend и действующий `DEV_API_URL`, затем повторить основной путь
на реальной модели. Обязательные новые методы или поля frontend не запрашивает.
Проверки и точные ограничения перечислены в `TESTING.md`.
