# QA: запуск и чтение результатов

Актуальный сквозной аудит интегрированного приложения: [full-recheck.md](full-recheck.md). Включает реальные Gemini вызовы и найденные ошибки семантики; число passed tests не является точностью модели. Воспроизводимые вымышленные входы — qa/fixtures/live-semantic-regressions.json, изменённый checklist — qa/fixtures/live-apology-checklist.json.

Проверка требования о дальнейшей адаптации к Dynamics 365: [архитектура, ограничения упаковки и варианты размещения](dynamics-readiness.md). Возможность адаптации отделена от ещё не проверенной интеграции в tenant.

QA работает в `feat/qa` от опубликованного main. Требования: Python 3.11+; audit/prepare/compare используют только стандартную библиотеку. Для backend tests нужны зависимости проекта из корневого README.

```powershell
python -m qa.audit C:\private\dev.json qa\local-results\data-audit.json
python -m qa.prepare
python -m unittest qa.test_compare qa.test_audit_selection -v
python -m pytest backend/tests qa -q
python -m qa.compare C:\private\run.json --output C:\private\report.json
python -m qa.render_report C:\private\report.json C:\private\report.md
```

Создайте `qa/local-results/` перед записью аудита. `qa.prepare` по умолчанию использует опубликованный обезличенный `qa/data-audit.json`; при другом DEV сначала обновите его осознанно и пересмотрите группы. Изменение выборки после настройки модели требует новой версии и объяснения.

- [Данные и выборка](data-review.md): фактический DEV, отсутствие Ground Truth, группировка.
- [Человеческая разметка](annotation.md): A/B, согласование и происхождение ответов. Офлайн-форма: `qa/annotation.html`.
- [Интеграция](integration.md): уровни mock/live, приёмочные тесты и запросы агенту 1.
- [Защита](demo-script.md): сценарий до пяти минут.
- [Статус проверки](status.md): выполненное, сбои, неизвестное.
- [Независимые backend-проверки](backend-findings.md): воспроизведение блокировки HTTP и ограничения телеметрии.
- [Независимые AI-проверки](ai-review.md): actual request payload с MockTransport, все попытки и ограничения live-проверки.
- [Проверки UI](ui-review.md): pure-function tests, source review и воспроизведение нулевого числа штатных тестов.

После восстановления работы выполнена новая проверка опубликованных веток: [AI](ai-revalidation.md), [UI и браузерный процесс](ui-revalidation.md), [QA-утилиты и A/B-согласование](qa-tooling-review.md). Эти документы обновляют исторические reviews выше. UI tests=0 исправлен. [Статус](status.md) содержит актуальные числа, неудачные попытки и оставшиеся ограничения. [Браузерный UX формы разметки](annotation-browser-review.md) пока не проверен: сама форма и её JS harness проверены отдельно.

Для двух независимых разметчиков добавлены `python -m qa.adjudicate compare` и `python -m qa.adjudicate finalize`. Полные команды — в [инструкции разметки](annotation.md). Согласие A/B не является точностью AI; финальный файл создаётся только после явных решений человека и сохраняет оба оригинала.

Для проверки запущенного обычного backend без AI используйте `python -m qa.smoke_backend --base-url http://127.0.0.1:8765`. Команда создаёт один вымышленный диалог/задание в отдельной локальной базе и ожидает `provider_not_configured`, пустые баллы и сохранение ошибки в JSON/CSV. Это отрицательный smoke HTTP/очереди/экспорта, не успешная модельная оценка. Сервер должен быть локальным; запуск с настроенным провайдером не относится к этому сценарию.

## Отчёт сравнения

Точная QA-only JSON-схема описана в docstring `qa/compare.py`; это не замена `backend/app/contracts.py`. Исходные backend значения true/false/"N/A" преобразуются явно в yes/no/na; числовые ступени остаются числами. Custom rubric пока требует отдельного адаптера сравнения; нельзя просто изменить checklist_hash и применить старые веса.

Сначала замораживается manifest ожидаемых разговоров. Выбираются один split, один mode=mock/live, один reference_source. Для accepted reference обязательны complete, совпадающие transcript/checklist hashes и все восемь допустимых ответов. Не завершённые и спорные метки показываются отдельно.

Отчёт содержит совпадение по каждому критерию, N/A FP/FN и запрещённый N/A, MAE вычисленного итога, грубые ошибки TP/FP/FN/TN и необработанные положительные примеры. Каждая метрика сопровождается знаменателем; результаты повторяются по языкам. Без размеченных пар MAE/agreement равны null, не нулю.

Первичная метрика относится к attempt_number=1. Вторичная — к первому валидному успеху с повторами. Ошибки первой попытки, пропавшие номера, незапущенные разговоры и все попытки остаются видны. Не выбирать лучший из нескольких ответов после просмотра меток. В отчёт входит только original_ai; апелляции/final игнорируются. MAE пересчитанного QA балла и MAE сохранённого первоначального original_score.total показываются раздельно, с покрытием и пропущенными/невалидными итогами. Расхождения видны в JSON и Markdown; ошибка производственного калькулятора не скрывается за правильными ответами по критериям.

Стоимость — сумма всех попыток, включая неуспешные, только если она известна; иначе total=null с известной частичной суммой и покрытием. Время попыток не выдаётся за время UI/очереди/backoff. Прямой экспорт backend пока не содержит всей телеметрии провайдера; ограничения отмечать явно.

Истинные результаты и источники хранятся вне Git или в игнорируемых `qa/private/`, `qa/local-results/`. В отчёт не переносить exception bodies, исходные транскрипты, raw_response, API keys или аудиоссылки. При ревью staging дополнительно проверить отсутствие этих данных.

`qa/export_run.py` преобразует backend JSON export + sidecar, записанный при отправке заданий, в этот формат. Поля sidecar и команда находятся в docstring. Не угадывать attempt number/mode по сортировке экспорта. Записанная единица здесь — backend evaluation job; количество внутренних вызовов/повторов провайдера остаётся неизвестным. Сравниватель сохраняет это ограничение в отчёте.

`docs/qa/measurement-readiness.md` — текущий отчёт без запусков и без меток, не результат измерения AI. Реальные отчёты после разметки/запусков формируются командами выше. Читаемый Markdown дополняет подробный JSON, в котором остаются ID и результаты каждой попытки.
