# Официальный экспорт результатов JSON 1.0

Источники требований: **CQA Student Guide Appendix Results**, страницы 1–3, и
**Chat Quality Checklist**, страницы 1–3. Исходные PDF, диалоги организаторов,
подписанные ссылки и ключи в репозиторий не включаются.

`backend/app/official_export.py` строит отдельный официальный документ. Внутренний
экспорт со снимками чек-листа, исходным ответом AI, историей и диагностикой остаётся
отдельным форматом. В официальный файл не добавляются поля приложения.
Для сдачи используются только **исходные автоматические результаты** выбранного запуска.
Принятые или отклонённые апелляции не меняют результаты, передаваемые организаторам.

## Вызов

```python
from backend.app.official_export import (
    OfficialExportError,
    build_official_export,
    validate_official_export,
    official_results_schema,
)

try:
    payload = build_official_export(
        conversations=dataset_conversations,  # Полный сохранённый исходный набор.
        evaluations=selected_evaluations,     # Ровно одна выбранная попытка на ID.
        team_name="cuda cuda",
        dataset_kind="dev",                  # dev / prod / test, явно из Dataset.
    )
except OfficialExportError as exc:
    report = exc.report                       # Показать причины в интерфейсе.
else:
    report = validate_official_export(
        payload, dataset_conversations,
        evaluations=selected_evaluations,
        dataset_kind="dev",
        expected_team_name="cuda cuda",
    )
```

Модуль выполняет только расчёт и проверку: он не читает окружение, не обращается к
провайдеру и не сохраняет/отправляет файлы. Маршрут приложения выбирает один Run и
его актуальную попытку для каждого диалога; модуль не выбирает самостоятельно
старую успешную оценку вместо последней незавершённой или неудавшейся попытки.
При передаче нескольких оценок одного диалога возвращается ошибка.

`validate_official_export` принимает Python-объект либо исходный JSON как строку
или UTF-8 bytes. Для исходного JSON проверяются также повторяющиеся ключи,
комментарии, лишние запятые, нечисловые NaN/Infinity и кодировка. После обычного
`json.loads` восстановить потерянную информацию о повторяющихся ключах нельзя.

`official_results_schema()` возвращает JSON Schema 2020-12 из тех же перечней
критериев и шкал, что использует валидатор. Сохранение схемы в
`contracts/official-results.schema.json` выполняет общий генератор контрактов.
JSON Schema описывает структуру; принадлежность исходных ID, реальные номера
реплик, происхождение модели и арифметику необходимо проверять функцией.
Runtime-валидатор принимает только допустимые числовые ступени: `7` и `7.0`
равнозначны. Строки, boolean, дробные значения между ступенями и нечисловые
NaN/Infinity недопустимы. Builder записывает ступени целыми числами.

## Полнота и происхождение

- `dev` требует 65 записей; `prod` — 10. Эти требования применяются только к
  набору, явно объявленному официальным. `test` использует размер своего набора.
- У `dev`/`prod` `conversation_id` берётся только из сохранённого `external_id`.
  У ручного тестового транскрипта без `external_id` используется сохранённый
  стабильный `Conversation.id`. Такой fallback никогда не применяется к DEV/PROD.
- Нужны все исходные ID ровно по одному; совпадения количества недостаточно.
  Пропуск, лишний или повторный ID блокирует выгрузку.
- Исходный набор должен быть полным. Валидатор не может обнаружить, что вызывающий
  код вместо настоящего набора передал другой набор того же размера, поэтому
  маршрут передаёт неизменяемый состав сохранённого Dataset.
- `queued`/`running`, отсутствующая оценка, неполная `completed` и нерассчитанный
  итог блокируют экспорт. Они не превращаются в фиктивные `error` или нули.
- Сохранённая `failed` с причиной даёт `status: "error"`, `criteria: []`,
  `score: null`, `error: "причина"`. Это разрешённая строка, она учитывается в
  количестве и сопровождается предупреждением. Сам статус ошибки не блокирует
  файл.

Имя модели берётся из сохранённого `ai_draft.models_used`, с fallback к
`ai_draft.model`. Для неудавшейся оценки учитываются только записи
`ai_execution.attempts`/`ai_draft.execution.attempts`, где
`network_attempted == true`. Модель не подставляется из текущих настроек.
Неизвестные фактические метаданные блокируют экспорт, в том числе когда все
попытки завершились до вызова провайдера и нет ни одной реально вызванной модели.
Это отдельная ошибка происхождения данных, а не запрет `status: "error"`.

Для Gemini режим — `external_api`; для сохранённого провайдера `local` — `local`;
совмещение режимов — `hybrid`. Несколько уникальных имён перечисляются в одном
`model.name`. Опциональный `expected_models=[{"name": "...", "mode": "..."}]`
позволяет передать подтверждённый режим неизвестного провайдера и проверить
ожидаемый состав моделей; он не заменяет отсутствующие факты запуска. Если
проверяется внешний файл без `evaluations` и без `expected_models`, формат имени
проверяется, но отчёт содержит `model_provenance_unverified`.

## Критерии и расчёт

| Внутренний ID | Официальный ID | Значения | Вес |
| --- | --- | --- | --- |
| 1 | contact | true / false | 10 |
| 2 | discovery | true / false / null | 15 |
| 3 | identification | true / false / null | 20 |
| 4 | consultation | 0, 5, 10, 15, 20 / null | 20 |
| 5 | empathy | true / false | 15 |
| 6 | dialogue | 0, 4, 7, 10 | 15 |
| 7 | closure | true / false / null | 5 |
| 8 | critical | true / false | 0, отдельный флаг |

Для успешного результата обязательны все восемь критериев, каждый один раз,
непустое `rationale` и непустой массив уникальных `evidence_turns`. Внутренние
стабильные ID сообщений преобразуются в позиции **с 1 по полному исходному
массиву**, включая клиента, бота и system/event. Порядок не меняется.

Экспортируются **ai_draft.criteria** и **original_score** до решений проверяющего.
`value`, `rationale` и `evidence_turns` получаются из исходных AI-значений,
обоснований и ID сообщений. Официальное имя `score.final_score` обозначает итог
автоматической оценки; оно не означает внутреннее поле `Evaluation.final_score`.
`critical_flag` также берётся из исходной автоматической оценки.

AI-критерии заново проверяются и пересчитываются общим `calculate_score`;
несовпадение с сохранённым `original_score` блокирует выгрузку. Если исходный
результат отсутствует или повреждён, корректные `final_criteria`/`final_score`
после ручной проверки не используются как замена. Проверка файла с параметром
`evaluations` сверяет его именно с исходными автоматическими результатами:
файл с математически корректными ручными исправлениями отклоняется.

Внутренний архив и интерфейс продолжают хранить и показывать решения человека,
`final_criteria`, `final_score` и историю апелляций. Экспорт ничего не меняет
в этих данных, исходном `raw_response`, AI-результате или снимке чек-листа.

`null` означает N/A: вес исключается, оставшиеся веса нормализуются до 100.
Числовая ступень делится на максимум шкалы, затем умножается на вес. Для dialogue
значение 7 означает `7 / 10 * 15 = 10.5` баллов. Округляется только общий итог до
двух знаков. Пример Да/N/A/N/A/15/Да/7/Да даёт **85.38**. `critical_flag`
равен значению critical и не обнуляет итог.

Официальный формат не является универсальным форматом произвольного чек-листа.
Выгрузка блокируется при изменении ID, веса, типа, ступеней, условий N/A или
смысла формулировок снимка. Изменения номера версии, названия набора, порядка
критериев и пробелов допустимы. Консервативная проверка формулировок намеренно
не пытается автоматически доказать эквивалентность другой формулировки.

## Отчёт и файлы

Отчёт возвращается отдельно от официального JSON:

```json
{
  "valid": false,
  "dataset_kind": "test",
  "errors": [{
    "code": "unfinished_evaluation",
    "path": "results",
    "message": "Оценка ещё ожидает выполнения или выполняется; дождитесь завершения.",
    "conversation_id": "synthetic-source-1"
  }],
  "warnings": [],
  "counts": {"expected": 1, "actual": 0, "ok": 0, "error": 0}
}
```

Организаторы требуют `results/dev/results.json` и `results/prod/results.json`
в корне репозитория, UTF-8 и опубликованные файлы до стоп-кода. Этот модуль не
создаёт вымышленные PROD-результаты и не выполняет публикацию. Перед передачей
проверяются полный набор, фактическая модель и исходные автоматические оценки; публикация
официальных результатов выполняется отдельным явно разрешённым действием.

Содержательные проверки модуля:

```console
python -m pytest backend/tests/test_official_export.py -q
```

Фикстуры синтетические, внешние API не вызываются. Проверяются расчёт 85.38,
флаги, принятые и отклонённые апелляции через сервис/SQLite, неизменность
официального файла после ручных решений и сохранность исходного ответа, версии и совместимость,
ошибки/незавершённые попытки, модельные метаданные, строгие типы, полный набор ID,
кодировка, формат и полнота доказательств.
