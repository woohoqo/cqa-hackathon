# Синтетическая проверка применимости N/A

Это проверка конкретной семантической регрессии по формулировкам чек-листа.
Ожидания составлены командой из синтетических диалогов, **не являются эталонами
организаторов** и не измеряют точность на DEV/PROD или новых неизвестных данных.

Матрица зафиксирована до испытания нового промпта:

- `qa/fixtures/na-regression-conversations-v1.json` и соответствующий
  `na-regression-expectations-v1.json`: первые шесть случаев, коммит `dddc1c6`.
- `qa/fixtures/na-regression-conversations-v2.json` и соответствующий
  `na-regression-expectations-v2.json`: те же шесть без изменений плюс три
  отрицательных контроля, коммит `d9ba31c`.

В каждой из RU/KZ/EN проверяются три ситуации:

| Ситуация | Ожидание по №2 | Основание |
| --- | --- | --- |
| Запрос ясен с первой реплики | N/A | Данных для ответа хватало с самого начала |
| Неясно, поддержка или офис; оператор уточнил и ответил | Да | Недостающая существенная деталь выяснена до ответа |
| Оператор предположил поддержку и проигнорировал уточнение про офис | Нет | Требуемое уточнение пропущено, известная деталь не учтена |

Ясные RU, KZ и EN используют точные ранее опубликованные синтетические реплики.
Ясный EN — тот же звонок с предложением личной оплаты в обход компании; №8
должен остаться `true`. В отрицательных контролях фиксируются только однозначные
№1/2/3/8. №4/5/6/7 не получают искусственно заданных эталонов: их изменения
показываются для разбора. Во всех случаях сравниваются все восемь результатов.

Замена всех ответов №2 на N/A провалит шесть применимых контролей. Совпадение
общего балла недостаточно: ошибочные `Да` и корректные N/A могут дать одинаковые
100 при остальных максимальных оценках.

## Протокол

1. Сначала выполнить девять оценок исходным промптом. Использовать неизменённый
   официальный снимок чек-листа и модель/настройки, выбранные для сравнения.
2. Затем выполнить ту же матрицу кандидатом. Повторения заранее ограничить;
   не повторять запросы до получения удобного результата.
3. Сохранить все ошибки и все фактические сетевые попытки, включая повторы
   провайдера. Не исправлять значения руками перед сравнением.
4. Сравнить №2 отдельно по языкам и ситуациям, затем остальные критерии, флаг,
   баллы, модель, версию промпта, число попыток и расход токенов.
5. Зафиксировать оставшиеся расхождения и нестабильность повторений. Даже
   отсутствие ошибок в этих девяти случаях не доказывает общую точность.

Live runner, авторизация и необработанные ответы остаются только в ignored
`private/`. Этот пакет не содержит live runner и сам не вызывает провайдера.
Не включать DEV/PROD или чужие реальные записи в эту матрицу.

## Сравнение сохранённых запусков

Каждый локальный архив должен содержать:

```json
{
  "conversations": ["полные сохранённые Conversation, включая внутренние ID"],
  "evaluations": ["по одной полной сохранённой Evaluation на каждый из девяти ID"]
}
```

В примере строки обозначают объекты контрактов, а не допустимый входной файл.
Реальные архивы передаются в CLI:

```console
python -m qa.semantic_regression --baseline private/na-baseline.json --candidate private/na-candidate-1.json --output private/na-comparison-1.json
python -m qa.semantic_regression --baseline private/na-baseline.json --candidate private/na-candidate-2.json --output private/na-comparison-2.json
```

Python API: `compare_runs(baseline_archive, candidate_archive)`.
`summarize_run(archive, fixtures, expectations)` проверяет один архив.
`load_matrix()` возвращает текущую frozen V2; для V1 можно явно передать её JSON
в обе функции. В отчёт включаются SHA-256 входной матрицы и ожиданий.

Перед сравнением проверяются полный набор исходных ID, точные тексты/роли/время
и ID сообщений, язык/канал, официальный снимок, полнота критериев и пересчёт
баллов. Изменённые человеком финальные критерии блокируются: это сравнение
ответов модели. Завершившаяся ошибка обработки остаётся ошибкой с отсутствующим
баллом; незавершённый запуск блокируется. Неизвестная цена/usage не превращаются
в ноль. Число `recorded_network_attempts` означает только попытки, сохранённые
в execution metadata; отсутствие metadata показывается отдельно.

В отчёте есть `criterion_deltas`, `introduced_mismatches`, `resolved_mismatches`,
ожидания и фактические значения каждого случая. У дельт нефиксированных
критериев стоит `asserted: false`; они не объявляются регрессией автоматически.
`completed_model_changes` показывает нарушение сравнимости по имени модели
или провайдеру. Отчёт не содержит транскриптов, raw response или секретов.

## Локальные проверки

```console
python -m pytest qa/test_semantic_regression.py qa/test_ai_acceptance.py -q
```

Первый файл проверяет матрицу и сравнение на явно вымышленных результатах:
ошибочные ID/тексты/снимки, скрытые исправления, пропуски, ошибки, подмену всех
ответов N/A, отдельность грубого флага и нефиксированные критерии. Второй
использует `httpx.MockTransport`; wire fixtures согласованы с обязательным
`applicability` нового AI-промпта. Никаких реальных запросов в этих тестах нет.
