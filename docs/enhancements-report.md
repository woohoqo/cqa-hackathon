## Что изменилось

- Один существующий интерфейс получил этапы «Загрузить → Оценить → Выгрузить», выбор набора,
  запуска, версии правил и счётчики очереди. Без выбранного запуска показаны входные диалоги,
  без подстановки старых оценок. Карточки, апелляции, история и экспорт ограничены запуском.
- Добавлены неизменяемые manifests наборов и снимки запусков. Миграция прежних данных
  добавляет контекст, не переписывая исходные записи. Повторный импорт идемпотентен.
- «Повторить только ошибки» создаёт новые попытки только для последних failed-записей.
  Успешные результаты, низкие оценки, N/A и критический флаг не повторяются. Повтор использует
  исходный snapshot. Транзакция и IDs неудачных попыток защищают от повторного клика, даже если
  новая попытка уже успела снова упасть. История доступна отдельным endpoint.
- Начальный POST имеет idempotency key; интерфейс сохраняет его при неизвестном исходе
  сетевого запроса в текущей сессии. Изменение правил создаёт новый запуск.
- Числовая сортировка окончательного балла учитывает апелляции; пустые/failed/pending идут
  после оценённых, равные баллы сохраняют исходный порядок. Сортировка выполняется до
  пагинации всей выборки; фильтры сохраняют выбор, смена набора/запуска его очищает.
- Официальный JSON 1.0 отделён от прежнего JSON/CSV-архива. Сервер проверяет полную
  принадлежность набору, IDs/число строк, восемь criterion_id, строгие типы и ступени,
  rationale/evidence, все исходные роли в нумерации с 1, N/A-арифметику и critical_flag.
  DEV требует 65 строк, PROD — 10, TEST — ровно состав собственного manifest.
  Корректные processing errors остаются в файле с предупреждением. Отсутствие данных
  о фактически использованной модели — отдельная ошибка метаданных, не нулевая оценка.
- Модель/модели, snapshot, время завершения, usage и попытки сохраняются с конкретной
  оценкой. Отмена по внешнему deadline также сохраняет известные сведения о попытках.
- Gemini получил основной ключ и два резерва, отдельные клиенты, общие для очереди
  состояния ключей/квот, ограниченные повторы и deadline. Модель и настройки при смене
  ключа не меняются. Safety/неправильный запрос не обходятся резервами. SDK не выполняет
  скрытых повторов: транспорт делает один HTTP-запрос, повторы контролирует сервис.

Существовавшие расчёт, версионирование, доказательства, импорт, апелляции и сохранение
повторно проверены. Формулы и официальный чек-лист не изменялись. Пример из задания — **85,38**.
Общие контракты и OpenAPI регенерированы; схема официального файла также генерируется из валидатора.

но выдаёт применимый ответ. Семантический дефект остаётся; successful/completed не означает
правильную оценку. Старые наблюдения QA не удалены, issue #13 не закрыт успешным повтором.

## Настройки и ограничения

В существующий корневой серверный `.env` добавить при наличии:

```dotenv
GEMINI_API_KEY=
GEMINI_API_KEY_BACKUP_1=
GEMINI_API_KEY_BACKUP_2=
GEMINI_MODEL=gemini-3.5-flash-lite
AI_PROVIDER=gemini
```

Основной уже заполнен локально; повторно вводить его не требуется. `scripts.init_env`
не перезаписывает файл. Пустые резервы разрешены. Перезапустить backend после изменения.
Условные quota groups: `GEMINI_QUOTA_GROUP`, `GEMINI_BACKUP_1_QUOTA_GROUP`,
`GEMINI_BACKUP_2_QUOTA_GROUP`. Задавать разные группы только при известных разных квотах;
разные владельцы ключей не подтверждают независимость. Неизвестные группы консервативно
учитываются совместно. Настройки attempts/deadline подробно описаны в README и AI README.

Работать одним процессом Uvicorn: gate/circuits общие внутри процесса, не между процессами;
после рестарта состояния соединений проверяются заново. Резервы реально не проверялись.
Ключи, полный API URL, реальные записи, базы и source PDFs отсутствуют в отслеживаемых файлах.

Точность/MAE/agreement с эталонами организаторов **не измерены**: подтверждённая человеческая
разметка отсутствует. Реальное прослушивание всех исходных звонков и будущий контрольный набор
не проверялись заново. Обработка transcript звонка проверена; аудиораспознавание не добавлялось.
Все выгрузки в этом этапе тестовые. Официальная отправка DEV/PROD не выполнялась.

Запуск и пятиминутный сценарий находятся в [README](../README.md). Для полноценного тестового
экспорта одного диалога используйте `contracts/demo-single-conversation.json` и v1;
для набора из четырёх входов требуется четыре результата, нельзя подставлять старые оценки.
