## Фактический запуск backend + QA

Из отдельной QA-копии:

```powershell
python -m venv .venv-clean
.venv-clean\Scripts\python -m pip install -c requirements.lock -e ".[dev]"
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
Remove-Item Env:CQA_SKIP_ASYNC_TESTS -ErrorAction SilentlyContinue
.venv-clean\Scripts\python -m pytest backend/tests qa -q
node qa/test_annotation.cjs
.venv-clean\Scripts\python -m pip check
```

Последний полный результат после добавления A/B: **176 passed, 13 skipped, 1 warning, 38 subtests passed in 9.59s**. JS формы PASS, зависимости совместимы. Native Windows asyncio работает. Пропущены 12 опциональных probes `test_product_contract.py` без единого адаптера и модуль AI acceptance, потому что AI ещё отсутствует в main-основе QA-ветки. Конкретные backend acceptance выполнялись; те же независимые AI acceptance отдельно прошли на AI-ветке. Пропуски не считаются pass.

Новый локальный сервер запущен из этого venv через `uvicorn backend.app.main:app --host 127.0.0.1 --port 8765`, с `.env`, скопированным из `.env.example`, отдельной SQLite и localhost CORS. По сравнению с README изменён порт и отключён reload для стабильности прогона; автоматический reload не проверен. `python -m qa.smoke_backend --base-url http://127.0.0.1:8765` прошёл за 0,234 с: это длительность всего локального smoke, не latency внешней модели. Неудачная оценка сохранена в обоих экспортных форматах, original/final остаются null.

Среда locked: FastAPI 0.162.0, Pydantic 2.14.3, HTTPX 0.28.1, pytest 9.2.0, Uvicorn 0.54.0. Starlette предупреждает об устаревшем httpx TestClient; переход на httpx2 не выполнялся вне владения QA.

## Что нужно для измерения и финальной защиты

1. Люди независимо заполняют пилот A/B, обсуждают разногласия, подтверждают группы сценариев; затем размечают выборку. Хеши фиксируют версии, но не доказывают независимость людей. Holdout не передаётся AI для настройки. Если он ранее использовался, считать его development validation.
2. Участник 1 интегрирует опубликованные AI/UI/QA PR и согласует telemetry/correlation. QA не меняет общий формат самовольно и не объединяет main.
3. На интегрированной версии с локально настроенным провайдером выполнить live контрольный запуск и injection, затем зафиксированный набор с журналом всех попыток. После этого считать метрики **исходного AI**, отдельно от апелляций.
4. Провести полный прогон [сценария защиты](demo-script.md) до пяти минут. Неполученные точность/стоимость не заменять оценками другой модели или синтетическими результатами.
