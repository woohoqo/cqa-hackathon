# Независимый аудит официальной выгрузки

Проверка основана на `CQA_Student_Guide_Appendix_Results-1.pdf` (3 страницы), Student Guide и исходном Chat Quality Checklist. Исходные PDF, ответы API, транскрипты, сырые ответы модели и диагностические архивы остаются в игнорируемой локальной папке `private/`.

Дополнительное требование текущей сдачи от пользователя: выгружать исходные автоматические оценки, а не исправленные человеком результаты апелляций. Само приложение продолжает показывать и хранить обе версии. Название официального поля `score.final_score` не означает разрешение подменить ответ модели решением проверяющего.

## Что проверяется

`qa/audit_submission.py` — отдельная проверка готового файла, а не генератор. Она не использует экспортёр или калькулятор backend, не вызывает модель, не читает `.env` и не исправляет входные данные.

- Корректный UTF-8 JSON без повторяющихся ключей, NaN, Infinity и лишних полей. Обязательны `schema_version: "1.0"`, настоящее `team_name`, `model` и `results`.
- Для DEV: ровно 65 исходных записей, 60 `agent chat` и 5 `voice call`, группа `DEV`. Для PROD: 10 записей. Набор `conversation_id` в выгрузке совпадает с полным ответом API, без пропусков, дубликатов и посторонних ID. Внутренние ID приложения не подставляются.
- Сохранённые сообщения совпадают с API по количеству, порядку, исходной роли, тексту и времени. Проверяются и клиентские сообщения, и bot/system/события, а не только оператор. Стабильные внутренние ID сообщений не повторяются.
- Архив содержит ровно одну явно выбранную оценку каждого диалога из одного запуска. Запущенные и незавершённые оценки не считаются результатами. Историю повторных попыток следует хранить отдельно от выбранного набора.
- Успешный результат содержит восемь официальных кодов ровно по одному: `contact`, `discovery`, `identification`, `consultation`, `empathy`, `dialogue`, `closure`, `critical`.
- Логические значения — JSON `true`/`false`; N/A — `null` только для discovery, identification, consultation, closure. Шкалы: consultation `0/5/10/15/20`, dialogue `0/4/7/10`. Числа `7` и `7.0` равнозначны; строки и логические значения вместо числа отвергаются.
- Значения совпадают с `ai_draft.criteria`; `rationale` совпадает с исходным обоснованием после единственной разрешённой детерминированной замены подтверждённых источником имён, описанной ниже. Произвольные изменения текста не разрешены. `evidence_turns` строго целочисленные, с единицы; каждая позиция вычисляется из ссылки исходного AI на полный неизменённый массив сообщений. `raw_response` оценки совпадает с сохранённой исходной строкой draft.
- Используется исходный снимок официального чек-листа. Для проверки формулировок снимок сравнивается с `official_checklist()`; формула, веса и шкалы независимо записаны в аудиторе по PDF.
- Итог независимо пересчитывается через Decimal: веса `10/15/20/20/15/15/5`, числовое значение делится на максимум шкалы, N/A исключает вес, округляется только итог. Пример из задания даёт **85,38**. `critical` имеет нулевой вес, совпадает с `critical_flag` и не обнуляет сумму. Проверяется `original_score`, а `final_criteria` и `final_score` после апелляции не используются.
- Для ошибки допустимы только `status: "error"`, `criteria: []`, `score: null`, непустая сохранённая причина `error` с той же ограниченной заменой имён. Такая строка остаётся в наборе и даёт предупреждение, а не искусственный ноль. Ошибка обработки сама по себе не делает формат недопустимым.
- `model.mode/name` совпадают с фактически сохранёнными моделями draft и сетевых попыток. Настройки окружения и ещё не вызванные модели не подтверждают происхождение оценки. Неизвестное происхождение модели блокирует подтверждение файла.

## Как проверить реальный файл

Нужны три **приватных** входа:

1. Готовый официальный `results/dev/results.json`.
2. Неизменённый ответ API организаторов: `{ "isSuccess": true, "data": { "dataset_group_id": "DEV", "total_records": 65, "records": [...] } }`.
3. Снимок сохранённых данных `{ "conversations": [...], "evaluations": [...] }` или `{ "conversations": [...], "batch": { "evaluations": [...] } }`. Оценки здесь — ровно выбранные последние результаты данного запуска, по одной на исходный диалог; все предыдущие попытки остаются отдельным архивом.

Из корня репозитория с активированным виртуальным окружением:

```powershell
python -m qa.audit_submission results/dev/results.json private/dev-source.json private/dev-selected-archive.json --dataset-kind dev --team-name "cuda cuda" --report private/dev-independent-audit.json
```

Успех возвращает код `0`, несоответствие — `1`, недоступный файл/попытка перезаписать вход отчётом — `2`. В терминал выводятся только результат, числа записей/ошибок/предупреждений и SHA-256 файла результатов. Приватный отчёт содержит коды ошибок, пути полей и ID диалогов, без текстов транскриптов, обоснований или сырых ответов. SHA-256 всех трёх входов связывает аудит с конкретными байтами файлов. Не публикуйте приватный архив вместе с официальным файлом.

```powershell
python -m pytest qa/test_audit_submission.py -q
```

Юнит-проверки используют один явно синтетический диалог с клиентом, bot/system и оператором. Они не создают искусственный набор из 65 записей под видом DEV. Покрыты подмена апелляцией, потеря исходного ответа, ID, метаданные моделей, полный порядок сообщений, ссылки, типы, шкалы, округление, грубая ошибка и формат ошибки обработки. Тестовый набор не может пройти в режиме DEV/PROD.

## Проверка публикуемых текстов

Перед публикацией отдельно проверьте `rationale` и `error`, которые входят в официальный файл:

```powershell
python -m qa.audit_public_text results/dev/results.json --report private/dev-public-text-review.json
python -m pytest qa/test_audit_public_text.py -q
```

Сканер отмечает email, телефоноподобные длинные номера, IBAN, номера карт с корректной контрольной суммой, URL и характерные признаки ключей/паролей/подписей. В отчёте только путь поля и правило, без совпавшего значения. Код `1` означает необходимость ручной проверки; `0` — отсутствие срабатываний эвристик; `2` — невозможность завершить сканирование. Хеш привязывает отчёт к конкретному официальному файлу. Сканер не меняет формулировки, оценки или обоснования и не публикует данные. Ложные срабатывания возможны; имена, адреса и непредсказуемые форматы секретов могут быть пропущены. Отсутствие flags нельзя считать гарантией обезличивания.

### Разрешённая маскировка перед публикацией

По запрету пользователя на публикацию исходных персональных данных интегратор утвердил замену подтверждённых источником имён, в том числе имён операторов, на `[имя скрыто]` только в `rationale` и `error`. Это решение о приватности, а не изменение оценок или новая норма PDF. Исходные `ai_draft`, `raw_response`, обоснования и архив остаются неизменными в приватном хранении. Публичные значения, баллы, грубая ошибка, ссылки, IDs и статусы не меняются.

Правило ограничено явными представлениями RU/KZ/EN из сообщений того же диалога: грамматика `NAME`/`NAME_WORD` и исключения `NOT_NAMES` в `qa/review_source_privacy.py`. Не используется список всех имён, поиск любых слов с заглавной буквы или догадки о склонениях. Имена разбиваются на Unicode-токены `[^\W_]+`, сравнение через `casefold`. В публикуемом тексте заменяется полный непрерывный ряд этих токенов; пробелы/пунктуация внутри найденного имени входят в заменяемый фрагмент. Все символы снаружи остаются точно исходными. Из пересекающихся совпадений первыми выбираются более длинные последовательности: число токенов, затем длина соединённых пробелом токенов, затем лексикографический порядок; внутри одной последовательности — слева направо.

Аудитор независимо вычисляет эту проекцию, не импортируя helper backend, и требует точного равенства. Немаскированное подтверждённое имя, другой маркер, лишняя маскировка или изменение смысла приводят к ошибке. В диагностике `privacy.fields_transformed` показывает число полей, для которых ожидается такая замена; это поле не добавляется в официальный JSON. Обычные слова, совпадающие с короткими именами вроде Will/May, остаются известной неоднозначностью правила и требуют просмотра исходного контекста. Это не универсальное обезличивание.

Дополнительное сравнение с приватным источником:

```powershell
python -m qa.review_source_privacy results/dev/results.json private/dev-source.json --report private/dev-source-privacy-review.json
python -m pytest qa/test_review_source_privacy.py -q
```

Этот инструмент ищет повторение имён, введённых явным представлением (`меня зовут`, `my name is`, `менің атым`), явно обозначенных номеров счёта/идентификаторов и домашних адресов. Сопоставляются только исходные сообщения того же диалога. Отчёт содержит позицию публикуемого поля, номер исходной реплики, роль и вид совпадения, без найденного значения. Длинные дословные совпадения учитываются отдельно; общая фраза или термин политики без признака личных данных не становятся flags. Имя оператора в объяснении критерия представления отличается по контексту от личных данных клиента: роль показана для ручного решения, автоматического запрета или правки нет. Это ограниченный поиск по явным маркерам, не универсальное распознавание имён/адресов. Проверка не меняет результаты модели.

## Границы заключения

Успешный аудит подтверждает формат, полноту, происхождение и арифметику. Он не доказывает семантическую правильность модели или близость к скрытым эталонам организаторов. Он не заново интерпретирует сырой ответ модели: соответствие его разбора draft проверяется AI-валидатором и тестами сервиса. Сохранённый сырой ответ дополнительно проверяется на неизменность между полями архива.

Факт проверки конкретного реального DEV-файла фиксируется отдельным отчётом: число `ok/error`, хеш файла, проверки, ошибки/предупреждения и проверенный опубликованный коммит. Описание инструмента и успешные синтетические тесты не заменяют такой аудит. Публикация официальной сдачи выполняется интегратором после проверки; этот инструмент ничего не отправляет.
