## Формат и происхождение

[Официальный файл](../results/dev/results.json) использует JSON `schema_version: "1.0"`
из дополнения организаторов. Проверяются точное множество исходных ID, все восемь кодов,
строгие типы и ступени шкал, N/A, полный порядок реплик, итог с округлением только в конце,
отдельный `critical_flag` и фактически сохранённая модель. Пример из PDF даёт **85,38**.
Поле `final_score` официального файла берётся из **исходной автоматической оценки**;
решения по апелляциям остаются отдельно и не подменяют сдачу.

Проверка выполняется сервером, локальным валидатором CLI и отдельным аудитом
`qa.audit_submission` с независимым пересчётом Decimal и сверкой с исходным ответом API.
Номера `evidence_turns` начинаются с 1 по полному transcript, включая клиента, бота и события.
Ни один диалог не исключался из-за низкой оценки, N/A или грубого нарушения.

Для публикации имена из явных представлений в исходном диалоге заменяются маркером
`[имя скрыто]` только в публикуемом тексте обоснования/ошибки. Это детерминированное
сокрытие персональных данных того же диалога, не новое оценивание. Исходный `raw_response`
и AI-draft остаются неизменными; значения критериев, баллы и доказательства не меняются.
Аудит допускает только точно предусмотренное преобразование текста и отклоняет произвольные правки.
Дополнительные сканеры проверяют публикуемые тексты на признаки секретов и повторение явных
персональных данных источника. Это ограниченные проверки, а не универсальное распознавание всех PII.

Финальный независимый аудит: **65/65 ID, 65 `ok`, 0 ошибок структуры, 0 предупреждений**.
Преобразованы ровно четыре поля с одиночными именами операторов; все 520 обоснований

они не становятся нулевыми оценками и не блокируют файл только из-за `status="error"`.
