Исходный AI-ответ и снимок чек-листа сохраняются отдельно от решений проверяющего.
В приложении нет фиктивного провайдера, подготовленных оценок или кэша ответов.

## Запуск на другом компьютере

Нужны Python 3.11+, Node.js 22.12+ и pnpm 11 (`npm install --global pnpm@11`).
Репозиторий открыт для организаторов; для чтения авторизация не нужна. Для push нужен доступ collaborator.
При использовании подключения ChatGPT
его GitHub-приложению также нужен доступ к репозиторию; терминальный Git авторизуется отдельно.

PowerShell:

```powershell
git clone https://github.com/woohoqo/cqa-hackathon.git
cd cqa-hackathon
python -m venv .venv
.venv\Scripts\python -m pip install -c requirements.lock -e ".[dev]"
python -m scripts.init_env
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
```

Заполните `GEMINI_API_KEY` в корневом `.env`. Пример выбирает проверенную модель
`gemini-3.5-flash-lite`, `AI_PROVIDER=gemini` и `GEMINI_THINKING_LEVEL=high`.
Для полного DEV шаблоны задают `GEMINI_MAX_OUTPUT_TOKENS=32768` и
`GEMINI_TIMEOUT_SECONDS=60`: прежнего лимита ответа не хватало для части диалогов.
В ранее созданном `.env` обновите эти два параметра и задайте
`GEMINI_THINKING_LEVEL=high`, если там осталось `minimal`. Высокий thinking и больший
лимит ответа могут увеличить расход токенов и время оценки; это не гарантия точности.
Ключ, модель, temperature и остальные настройки сохраните. Для импорта DEV откройте
**Импортировать → API организаторов** и вставьте полную подписанную HTTPS-ссылку.
Группа подставляется из `group_id` в ссылке; её можно изменить перед загрузкой.
В обычном локальном режиме пустое поле использует `DEV_API_URL` из `.env`, если он заполнен.
Не перезаписывайте существующий `.env`, не добавляйте ключи в frontend или Git.
Переменные процесса имеют приоритет над `.env`; после изменения настроек перезапустите backend.

```powershell
.venv\Scripts\python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Backend обслуживает `frontend/dist`; сборка должна
существовать до запуска сервера. API: http://127.0.0.1:8000/docs; health: `/health`.
На macOS/Linux используйте `.venv/bin/python`; `python -m scripts.init_env` работает одинаково на всех ОС.
Все команды выполняются из корня проекта.

Ключ вводится один раз в каждой локальной копии. Повторный `scripts.init_env` сохраняет
существующий `.env` без изменений. Не повторяйте `Copy-Item .env.example .env` или
`cp .env.example .env`: эти команды могут затереть ключ пустым шаблоном.
`.env` намеренно не передаётся через Git: у каждого clone/worktree свой файл.
Если ключ «пропал», проверьте, из какой копии запускается backend, и нет ли пустой переменной
`GEMINI_API_KEY` в окружении процесса. Само приложение `.env` только читает.
На общем хостинге ключ задаётся один раз в серверных секретах; посетителям сайта он не нужен.

Для временной общей ссылки запустите защищённый режим демо:
`.venv\Scripts\python -m scripts.run_demo`, затем HTTPS-туннель к порту 8001.
Для доступа по ссылке без пароля добавьте `--public`; обычный запуск сохраняет вход по паролю.
Участникам нужен только пароль входа; Gemini использует ключ сервера. Демо сохраняет данные
в отдельной SQLite и начинает с четырёх синтетических транскриптов без готовых оценок.
[Запуск, остановка и ограничения временной ссылки](docs/shared-demo.md).
В общем демо ссылка вводится явно при каждом импорте, а адрес назначения ограничен API организаторов.
Загруженные диалоги видны всем участникам, которым передан пароль сайта.

Используйте один процесс Uvicorn, без `--workers`. SQLite и очередь находятся в игнорируемой
папке `data/`. Ожидающие задания продолжаются после перезапуска; прерванные выполнявшиеся
задания получают понятную ошибку и допускают новый запуск.

Для разработки добавьте backend параметр `--reload`, а во втором терминале выполните
`pnpm --dir frontend dev`. Интерфейс: http://127.0.0.1:5173. Vite передаёт `/api` на backend.
Другой адрес proxy задаётся через `CQA_BACKEND_URL` в локальном `frontend/.env`;
`VITE_API_BASE_URL` задаёт адрес API для отдельно размещённой сборки.

## Возможности и правила

На странице **Диалоги** доступны импорт, оценка и выгрузка. Выберите набор и конкретный запуск:
список, прогресс, повтор ошибок и официальный файл относятся только к этому контексту.
JSON-импорт по умолчанию создаёт тестовый набор; официальные DEV/PROD выбираются явно.
Ранее сохранённые диалоги и запуски получают контекст при первом запуске новой версии без
удаления исходных записей. Для DEV нужно 65 записей, для PROD — 10; тестовый набор сверяется
со своим списком входных ID.

**Повторить неудачные** повторяет только ошибки текущего запуска. Успех, низкий балл,
«Нет», N/A и грубое нарушение не являются ошибкой обработки. Повтор сохраняет исходный
снимок чек-листа, успешные оценки и апелляции; история попыток остаётся доступна отдельно.
Повторное нажатие с теми же ID ошибок не создаёт ещё одну попытку. Другой чек-лист требует
нового запуска. Сортировка по итоговому баллу учитывает решения проверяющего, а записи без
вычисленного балла остаются после оценённых.

Перед официальной выгрузкой сервер сверяет JSON `1.0` с дополнением организаторов:
исходные ID набора, восемь критериев, типы/шкалы, полную нумерацию реплик, пересчёт N/A,
отдельный critical-флаг и сохранённые сведения о моделях. Корректные `status="error"`
сохраняются в файле с предупреждением; нарушения структуры блокируют скачивание с указанием
проблемного ID. Архивный JSON/CSV содержит историю приложения и не является официальной сдачей.
В официальный файл входят **исходные автоматические оценки**, обоснования и баллы AI.
Решения по апелляциям его не меняют; они остаются в интерфейсе и внутреннем архиве.
В публикуемом тексте имена, подтверждённые явным представлением в исходном диалоге,
детерминированно скрываются маркером `[имя скрыто]`. Значения, баллы, доказательства,
исходный AI-draft и `raw_response` не меняются; произвольные изменения текста аудит отклоняет.
Тестовые файлы сохраняйте вне Git. Официальные `results/dev/results.json` и
`results/prod/results.json` публикуются только по отдельному запросу команды.

- DEV API, JSON и новые транскрипты; исходные роли, текст, время и стабильные ID.
- Пакеты оценок, очередь, статусы, понятные ошибки и повторный запуск.
- Неизменяемые версии чек-листа: произвольные критерии, секции, веса, шкалы и N/A.
- Доказательства с переходом к сообщениям, история запусков и сохранение после обновления страницы.
- Апелляции, решения проверяющего, отдельный окончательный результат и история решений.
- Выгрузка JSON с историей и CSV с итогами на странице диалогов.
- RU/KZ/EN, смешанный текст, транскрипты звонков и доступные ссылки на аудио.

Официальные правила: [contracts/official-requirements.md](contracts/official-requirements.md).
Да даёт полный вес; Нет — ноль; шкала делится на свой максимум, а не на вес.
N/A исключает вес из знаменателя, остальные веса нормализуются до 100. Округляется только
общий итог до двух знаков. Без применимого положительного веса итог отсутствует.
Грубая ошибка — отдельный флаг без обнуления результата. Контрольный пример №2/3=N/A
и №1/4/5/6/7=Да/15/Да/7/Да даёт **85,38**. У №6 максимум 10 при весе 15.

Для каждого допускающего N/A критерия модель сначала обосновывает применимость по
сохранённому условию. Противоречие между структурированным решением о применимости и
ответом отклоняется; сервер не заменяет оценку по словам в объяснении. Исходный ответ
сохраняется целиком. [Проверка N/A на RU/KZ/EN и её ограничения](docs/qa/na-live-recheck-20261108.md).

При ошибке или отсутствии ключа баллы не выдумываются. Провайдер получает весь транскрипт
и выбранный снимок правил; метаданные и аудиоссылки не отправляются. `.env.example` ограничивает
параллелизм до 1, задаёт 15 секунд между началами запросов и максимум 3 попытки на диалог.
Это настройки приложения, не обещание квоты Google. После 429 учитывается cooldown;
дневная квота требует повторного запуска позже. [Описание AI](backend/app/ai/README.md).

## Основной и резервные ключи

Заполните в серверном `.env`:

```dotenv
GEMINI_API_KEY=
GEMINI_API_KEY_BACKUP_1=
GEMINI_API_KEY_BACKUP_2=
```

Пустые резервы допустимы. Все подключения используют один `GEMINI_MODEL`, одинаковые
промпт и параметры; ключи посетителям не передаются. После изменения файла перезапустите backend.
Если известны проекты, задайте условные группы `GEMINI_QUOTA_GROUP`,
`GEMINI_BACKUP_1_QUOTA_GROUP`, `GEMINI_BACKUP_2_QUOTA_GROUP`. Одинаковая группа означает
общую квоту; пустая группа не подтверждает независимость. Разные владельцы ключей сами
по себе не дают независимых лимитов.

`AI_MAX_ATTEMPTS=3` — общий предел HTTP-попыток на диалог, включая переключения.
Для проверки обоих резервов должно оставаться достаточно попыток. Если старый `.env`
содержит `AI_MAX_ATTEMPTS=2`, значение 3 позволяет достичь обоих резервов при немедленном
отказе ключа/квоты; при двух временных попытках на каждом из первых двух нужен предел 5.
Общий deadline всё равно ограничивает весь диалог. Паузы и отключённые подключения
общие для очереди. Неверный ключ исключается до изменения конфигурации; safety-отказ и
неправильный запрос не обходятся резервом. Неизвестная стоимость/расход после таймаута
остаются неизвестными. Модель и время в карточке берутся из сохранённой оценки, а не из
текущего `.env`.

## Пятиминутная демонстрация

1. **0:00–1:00:** импортируйте `contracts/demo-single-conversation.json` как TEST. Это один явно
   синтетический транскрипт без готовой оценки. Выберите официальный чек-лист **v1** и оцените набор.
2. **1:00–2:00:** покажите результат, N/A, шкалу №6 и отдельный флаг. Нажмите доказательство,
   затем обновите страницу. Пакет KZ/EN можно запустить заранее.
3. **2:00–3:00:** замените смысл первого критерия на требование явного извинения
   («Да только при явном извинении; приветствие не считается»), сохраните новую версию,
   выберите её и повторно оцените диалог. Появится отдельный запуск; старый остаётся в списке.
4. **3:00–4:00:** вернитесь к запуску **v1**, подайте апелляцию, переключитесь в режим проверяющего,
   измените ответ с обоснованием и доказательством. Сравните исходный AI и окончательный итог.
5. **4:00–5:00:** для запуска **v1** нажмите «Проверить файл» и «Скачать results.json».
   Полный тестовый набор содержит одну запись; DEV/PROD на этом шаге не отправляются.
   Для KZ/EN и звонка используйте отдельный `contracts/demo-conversations.json` заранее.

Изменённый смысл критерия несовместим с официальным файлом: его запуск доступен во внутреннем
архиве, а сервер объясняет, почему его нельзя выдать за исходные восемь критериев.

Заранее проверьте квоту и соединение. Время ответа зависит от Google; ожидание и ошибку
показывайте честно. Сохранённый настоящий запуск показывайте с датой и версией.
Демонстрационная ручная корректировка не является человеческим эталоном.

## Проверки и ограничения

```powershell
.venv\Scripts\python -m pip check
.venv\Scripts\python -m pytest backend/tests backend/app/ai/tests qa -q
node qa/test_annotation.cjs
node --experimental-strip-types --test qa/test_ui_contract.cjs
pnpm --dir frontend test
pnpm --dir frontend build
.venv\Scripts\python -m scripts.export_contracts
```

Автотесты используют синтетические данные и изолированные провайдеры. Корневой `conftest.py`
блокирует настоящий HTTP в pytest даже при настроенном ключе. Живая проверка описана отдельно
в [актуальном отчёте доработок](docs/enhancements-report.md); предыдущий этап —
[docs/integration-report.md](docs/integration-report.md).

Обычный сервер предназначен для localhost; временное демо имеет общий пароль команды.
Переключатель ролей не является аутентификацией. Нет полноценного
контроля доступа, распознавания аудио и точной перемотки аудио по каждому сообщению.
Для длинных транскриптов действуют лимиты модели и таймауты, без усечения исходного текста.
Стоимость в `data/ai_usage.jsonl` неизвестна без подтверждённых тарифов и полного usage;
количество оценок не равно количеству HTTP-попыток. Подробнее о журнале — в описании AI.

Близость к эталонам организаторов не измерена: эталонные оценки не предоставлены.
Историческая ошибка «Да» вместо N/A в EN проверена повторно: профиль промпта v1.1.1
с high thinking прошёл зафиксированные проверки №2 на синтетических RU/KZ/EN.
Один повторный прогон потребовал отдельного retry структурно некорректного ответа;
[отчёт QA](docs/qa/na-live-recheck-20261108.md) сохраняет все итерации и ограничения.
Это проверка конкретных случаев, а не доказательство точности на новых транскриптах.
Успешные вызовы и структурные тесты не заменяют независимую человеческую разметку;
holdout не используется для настройки. Репозиторий открыт для сдачи; официальные
файлы результатов публикуются после проверки. Исходные реальные транскрипты, PDF,
SQLite, ключи, подписанные ссылки и приватные архивы в Git не входят.

## Контракты и команда

[AGENTS.md](AGENTS.md) фиксирует владение каталогами. Общие модели — `backend/app/contracts.py`;
API, примеры и генерируемые схемы — `contracts/`. Интерфейс AI:
`async evaluate_dialogue(conversation, checklist) -> EvaluationDraft`.
Общие форматы централизует агент 1; он же объединяет готовые ветки в main после проверок.
Каждый участник работает в отдельной копии/worktree, делает commit/push и проверяет удалённый SHA.
