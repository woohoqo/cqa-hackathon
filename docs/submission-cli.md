# Команда подготовки официальных результатов

Запустите актуальный backend локально. Его существующий `.env` должен содержать
рабочие `DEV_API_URL`, `GEMINI_API_KEY` и выбранные настройки AI. CLI не читает эти
секреты, не принимает подписанную ссылку и не меняет модель, prompt или профиль.
По умолчанию используется `http://127.0.0.1:8000`; `--api-base` разрешает только
loopback-адрес без credentials, пути, query и fragment. HTTPS-redirect не выполняется.

Из корня репозитория в установленном Python-окружении:

```console
python -m scripts.submit_results run --kind dev --group-id DEV
```

После выдачи контрольной группы организаторами укажите **точный выданный group_id**:

```console
python -m scripts.submit_results run --kind prod --group-id ВЫДАННЫЙ_GROUP_ID
```

Обозначение выше нужно заменить настоящим идентификатором; CLI не придумывает
контрольный набор. DEV требует ровно 65 исходных диалогов, PROD — ровно 10.
Неправильный набор блокируется до запуска модели. Имя команды по умолчанию —
`cuda cuda`, изменить можно через `--team-name`.

Команда импортирует набор через backend, выбирает точное текущее определение
исходного чек-листа из `default_checklist.py`, создаёт один пакет и опрашивает его
статусы. Изменённый пользовательский чек-лист не выбирается. Сохранённый prompt
каждого доступного AI-draft должен совпадать с `PROMPT_VERSION` текущего checkout;
старые ответы не принимаются за результат нового движка. У ошибок до draft нет
версии prompt в контракте; они остаются явными ошибками с фактическими метаданными.

По умолчанию выполняется **один дополнительный круг только failed-попыток**.
Завершённые оценки, включая нулевые баллы и N/A, не перезапускаются ради других
ответов. `--retry-rounds 0` отключает повтор; значения 0–3 задают общий лимит
повторных кругов сохранённого запуска. Возобновление команды не обнуляет счётчик.
Это внешние повторы заданий: у каждой оценки остаётся собственный ограниченный
бюджет AI-запросов. Причины вроде output limit могут требовать исправления
серверных настроек до повтора; CLI автоматически настройки не меняет.

После Ctrl+C, таймаута или обрыва сети повторите **ту же команду без `--new-run`**.
Состояние по умолчанию хранится в игнорируемой Git папке
`data/submission/dev/` или `data/submission/prod/`. Оно сохраняется до POST запуска;
при неоднозначном сетевом сбое повторяется тот же idempotency key. Если ID пакета
уже известен, повторного импорта и запуска нет. Повтор failed использует точные
ID старых попыток и также безопасно возобновляется. Одновременные команды с одной
папкой состояния блокируются OS-lock; аварийное завершение освобождает блокировку.

`--new-run` явно начинает новый запуск и сохраняет прежнее состояние в `history/`.
Это может повторно расходовать квоту. Используйте его для нового движка/источника,
а не для обычного продолжения. `--wait-seconds` задаёт время ожидания команды
(по умолчанию 3600), `--poll-seconds` — интервал опроса (2 секунды). Срок стоп-кода
CLI не знает; контролируйте время получения и публикации отдельно.

Серверная проверка и независимый локальный `validate_official_export` проверяют
полный исходный набор ID, восемь критериев, ссылки на полный массив сообщений,
арифметику, фактическую модель и **ai_draft.criteria + original_score** выбранных
попыток. Апелляции не подменяют автоматические результаты. Затем UTF-8 JSON
атомарно записывается в `results/dev/results.json` или `results/prod/results.json`.
Ошибки обработки сохраняются как официальные `status="error"`, а не нули.
Невалидный или незавершённый результат не перезаписывает существующий файл.

`--output` меняет путь только официального файла. `--state-dir` задаёт приватную
папку состояния; внутри репозитория допустимы только игнорируемые `data/` и
`private/`. В ней сохраняются отчёты проверки и все попытки по каждому запуску,
включая неудачные и исходные ответы модели. **Не публикуйте эту папку** или SQLite.
Подписанные URL, HTTP error bodies и исходные диалоги не выводятся в консоль.

CLI не выполняет commit/push и не создаёт фиктивный PROD-файл. После проверки
опубликуйте готовый официальный файл предусмотренным командой Git-процессом.

Тестирование без организаторского API и модели:

```console
python -m pytest backend/tests/test_submission_cli.py -q
```
